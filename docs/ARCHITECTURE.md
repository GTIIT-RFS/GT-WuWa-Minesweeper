# 架构与维护

## 游戏状态

`Game` 包含行列、雷数、格子数组、布雷状态、命中格与 ready / playing / won / lost / timeout 状态。首击时才均匀随机采样布雷，唯一保护是首格本身；邻格可能有雷。所有规则函数返回新对象，不修改输入。队列展开避免递归栈溢出。正确翻开所有非雷格就是胜利，旗子数量不直接决定胜利。

计时使用 `performance.now()` 的实际经过时间，不按 interval 次数累加；切到后台后回到页面会根据真实时间判超时。操作前再次检查截止时间，防止超时后还能获胜。对局时间规则和昵称在开局锁定；通过单一终态转移记录成绩，React StrictMode 不会重复记分。

## 存储边界

配置与成绩使用 v1 命名空间。配置导入按白名单字段与数值范围校验，不信任文件内容。损坏轻量数据回退默认。图片验证 MIME、体积、解码与像素上限；音频校验格式和体积，播放兼容性由浏览器确定。素材事务提交成功后才更新预览。替换或卸载时释放 object URL。浏览器存储不可用时展示错误，不阻止基本游戏。

配置 JSON 是布局/参数备份，不是素材备份。不要用配置导出来迁移全部站点数据。生产站点应配置 HTTPS、适当缓存策略和常规安全响应头。应用没有服务端和认证；管理员页面不是权限边界。

## 扩展路径

- 加图片槽：扩展 `ASSET_LABELS`，在需要的组件使用 `AssetImage`；不把二进制塞进 LocalStorage。
- 加音效事件：扩展 `AUDIO_LABELS` 与合成默认音映射，然后在用户动作或游戏事件调用 `playSound`。
- 加玩法：先定义状态与纯函数规则，在 engine 测试里加入可验证场景，再接入 UI。
- 加动画：集中在 `Explosion` 与 CSS；保留减少动态效果与清理定时器，不让动画阻止规则执行。
- 更改数据格式：提升版本，提供显式迁移；不要直接让旧数据被误读成新格式。

## 第一阶段验收层次

纯逻辑随机首击/边界测试 → 配置输入校验 → Chromium 桌面及触屏真实交互 → TypeScript 与生产构建。自动化随机数被固定以重现胜负局；生产环境仍使用 `Math.random`。本地排行榜不是防作弊或竞赛认证系统。
